## Шаг 1.5. Палитра кандидатов (C.32 — ДО оценки)

> Принцип C.32: архитектуру оценивают из палитры, а не из одного предложения. Критерий готовности — другой практик видит **минимум 2 структурно разных кандидата** с названными выигрышем и потерей каждого.

**Построй 2–5 структурно разных кандидатов.** Структурное различие = смена одного из: декомпозиции · аллокации (что где живёт) · носителя функции · размещения · грамматики интерфейса · механизма контроля · распределения ответственности · объёма свидетельств. Кандидаты, отличающиеся только описанием, — не разные.

Для каждого кандидата — одной строкой: **что меняет в структуре · ожидаемый выигрыш · известная потеря · constraint fit.**

**Чеклист режимов отказа trade-off (C.32:6) — прогони палитру:**
- **Локальный выигрыш прячет потерю в другом месте** — кандидат улучшает одну характеристику, ухудшая другую; назови и выигрыш, и потерю.
- **Нет реального выбора** — виден только один вариант (или «альтернативы» отличаются лишь словами) → палитра не построена, вернись и построй.
- **Идеальность-ярлык** — «меньше модулей / один универсальный модуль» — это лишь направление, пока не названы функции, характеристики, окно масштаба, безопасность, потери.
- **Перенос софтверной онтологии** — не тащи софтверную структуру в несофтверный холон по привычке (частая ошибка ИИ-генерации вариантов).

Палитра готова (≥2 структурно разных кандидата) → шаг 2: профиль ЭМОГССБ строй **по палитре** (сравнительный режим 2б — основной).

## Шаг 3. Вето-фильтр (conjunctive screening)

> Принцип: non-compensatory. Высокий статус по одной характеристике НЕ компенсирует блокер по другой.

Проверь каждое правило явно и выведи результат по каждому отдельно:

**Правило 1. Критические характеристики.**
Перечисли характеристики, помеченные как критические в Шаге 1, и их статус из Шага 2.
Пример: «Безопасность (критическая) → ⚠️ — правило не сработало».
→ Вывод: сработало / не сработало.

**Правило 2. Количество блокеров (❌).**
Перечисли все характеристики со статусом ❌ из Шага 2 (с названиями).
Пример: «❌ не найдено» или «❌ Безопасность, ❌ Эволюционируемость — итого 2».
→ Вывод: [N] блокеров — сработало (N≥2) / не сработало (N<2).

**Правило 3. Соотношение ⚠️ и ✅.**
Перечисли все ⚠️ и все ✅ из Шага 2 (с названиями).
Пример: «⚠️ Эволюционируемость, Современность, Безопасность (3 шт.) | ✅ Масштабируемость, Обучаемость, Генеративность, Скорость (4 шт.)».
→ Вывод: сработало (≥4⚠️ и 0✅) / не сработало.

**Итоговый вердикт:**
- Хотя бы одно правило сработало → **СТОП.**
  > «Решение НЕ проходит АрхГейт. Блокирующие условия: [список]. Рекомендация: [что исправить].»
  Перейди к шагу 5 и завершай.
- Ни одно не сработало → **Решение проходит вето-фильтр** → шаг 4.
